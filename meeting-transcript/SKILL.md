# 会议录音与转录稿整理

## 目标

形成可供研究和引用的完整会议记录。始终优先保证忠于原话、信息完整和来源可追溯，不把会议内容压缩为概括性纪要。

## 工作流程

1. **盘点材料**：识别原始音频、用户提供的原始转录稿、第三方转录稿、公司官方财报或公告，并记录各材料的名称、日期和链接或文件路径。没有任何会议原始材料时，请用户提供；音频无法取得或无法核听时，在交付说明中明确限制。
2. **确定底稿**：按“原始音频 > 用户提供的原始转录稿 > 第三方转录稿”的优先级确定底稿。第三方材料只用于补齐缺失内容，不得覆盖用户版本。
3. **逐段整理**：按实际发言顺序保留开场、陈述、提问、回答和追问，识别发言角色并修正明显的语音识别错误。
4. **补齐缺失**：用较低优先级来源补齐底稿缺失片段，并逐段标明补录来源；来源之间存在冲突时保留高优先级版本并说明差异。
5. **核验信息**：核对姓名、专有名词、日期和关键数字。涉及财务数据时优先查阅公司官方财报、业绩公告、监管公告或投资者关系材料。
6. **完整交付**：按会议进程分节输出完整 Markdown 整理稿，并在文末列出来源、补录情况和未能核验的事项。

## 来源处理

- 优先直接核听原始音频；有时间戳时保留时间戳，以便回溯。
- 将用户提供的原始转录稿视为次优先底稿，不因第三方版本表达更顺畅而替换它。
- 仅用第三方转录稿填补确实缺失的段落。使用以下标记包围补录内容：

```markdown
[补录开始｜来源：来源名称｜链接或文件：XXX｜时间戳：XX:XX]
补录内容
[补录结束]
```

- 无法确认发言人时标注“发言人待核实”；无法听清的内容标注“听不清”并附时间戳；专有名词、姓名或关键数字无法确认时标注“待核实”，不得猜测。
- 不得虚构不存在的音频内容、发言人身份、时间戳或来源。

## 忠实整理

- 保留开场、主持串联、管理层陈述、每轮提问、回答及追问之间的对应关系。
- 允许删除不影响含义的语气词、机械重复和口吃，允许修正能由上下文明确认定的识别错字。
- 不得删减实质信息，不得改变语气强弱，不得把假设改成事实，不得把管理层的限定条件、不确定性或回避性表达改写为确定结论。
- 不得将发言重组为 AI 的主题分析或投资结论。只有用户明确要求时，才在完整整理稿之外另附摘要。

## 数据核验

- 区分法定披露数字、管理层现场口径和管理层或分析师预测，不得混写。
- 现场发言与官方披露冲突时，保留现场原话，不静默篡改；紧随相关段落之后另起一段写明核验结果、依据和来源。
- AI 自行补充的解释、纠错依据、冲突说明和背景必须独立成段，并以全角圆括号包围，例如：

```markdown
（核验说明：公司官方公告披露该数据为 XXX，与现场口径 XXX 不一致。来源：公告名称、日期、页码或链接。）
```

- 无法通过可靠来源确认时明确写“待核实”，不要用常识或推断补足。

## 输出格式

- 标题写明公司、会议名称和日期，例如：`# 公司名称｜2026 年第二季度业绩电话会｜2026-08-15`。
- 正文按会议实际进程分节，使用明确的发言角色；已知姓名和职务时一并写明。
- 保持问答对应关系。每轮问答依次标注“提问”“回答”“追问”“补充回答”，不要把不同轮次合并。
- 默认输出完整 Markdown 整理稿，不用摘要替代正文。
- 文末设置“来源与补录说明”和“未核验事项”两个小节；没有对应内容时写“无”。
- 用户要求 PDF 时，在完整 Markdown 稿基础上制作 PDF，采用深色高对比正文和清晰字号，并在交付前检查文件能否正常打开、文字是否完整可读。

## 交付前检查

- 检查是否遗漏任何关键问答、追问、数字或管理层限定措辞。
- 检查补录段落是否完整标明来源，第三方材料是否仅用于补缺。
- 检查所有 AI 解释、纠错依据和背景是否独立成段并由全角圆括号包围。
- 检查公司、会议、日期、发言角色、专有名词和关键数字是否已核验或标注“待核实”。
- 检查文末是否明确说明音频核听限制和所有未能核验的部分。
